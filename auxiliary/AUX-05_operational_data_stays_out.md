# AUX-05 Operational data and why TTDF-shaped work stays out

**Self-taught. 25 minutes. No GPU.**

## Who this is for

- **TTDF / Coast Guard** — patrol, radar, interdiction, intelligence.
- Anyone tempted to “just try a sample” of production logs (Trade security tickets, Health, MPSDFS).

## The course rule, restated

The workshop is capacity building. It is not a clearance to move operational data onto a GPU.

Language models:

- invent coordinates and times that look plausible;
- leak whatever was in the prompt or the fine-tune set;
- do not replace a targeting or tasking process.

Pattern-finding on routes, tides and radar (N15) is a **different** class of model, with a different accreditation path.

## What you *can* take from the six days

- How to start an open-weight model on infrastructure you control (Day 1).
- How to refuse when the source is missing (Day 2).
- How to keep tools off the table (Day 3, T1-13).
- How to write the stop condition on a transfer card: *no operational feeds in any lab; any later project is a separate approval.*
